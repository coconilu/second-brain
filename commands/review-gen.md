对照可复用组件目录审查最近生成的代码并修复重复问题。

## 背景

首先理解可复用性标准：
- 项目中已有的导出函数、组件、hooks、工具函数、API 客户端和类型应该被复用，而不是重新实现。
- 严重等级：
  - **Critical**：完全重复 → 替换为 import，删除重复代码
  - **High**：高度相似 → 重构为使用已有实现
  - **Medium**：部分重叠 → 提取共享逻辑
  - **Low**：潜在可复用 → 添加注释标记

## 步骤

1. 读取 `.scan-review/catalog.md`。如果不存在，回复："未找到目录。请先运行 /scan-index。"
2. 运行 `git diff` 查看刚刚生成或修改的代码。
3. 对 diff 中的每个生成的函数、组件、hook 或 API 调用，对照目录检查：
   - 是否有已有条目具有相似的名称或签名？
   - 是否有已有条目实现了相同的目的？
4. 按严重等级分类每个发现。
5. 对 Critical 和 High 级别的发现应用修复（编辑生成代码以使用已有组件）。
6. 输出审查摘要：

```markdown
## 审查摘要

### Critical
- `{file}` 第 {N} 行：`{生成的代码}` 与 `{已有代码}` 重复。**已修复。**

### High
- `{file}` 第 {N} 行：`{生成的代码}` 与 `{已有代码}` 高度相似。**已修复。**

### Medium
- `{file}` 第 {N} 行：与 `{已有代码}` 部分重叠。**已标记。**

### Low
- `{file}` 第 {N} 行：可考虑复用 `{已有代码}`。**已记录。**
```

## 指南

- 仅在确信生成的代码重复了已有功能时才标记。误报会降低信任度。
- 重构时保留原有业务逻辑——仅修改实现方式以使用已有组件。
- 如果要复用已有组件需要修改其接口，则降级为 Medium 并建议接口变更。
- 除非必要，不要修改已有（非生成）代码。
- 如果没有发现重复，报告"未发现重复——一切正常。"
